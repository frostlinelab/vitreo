# AGENTS.md — Working Agreement for AI Contributors

Guidance for AI agents (and humans pairing with them) working on **Vitreo**, a renderer-agnostic Rust glass-material layer on wgpu. The physics deep-dive lives in [docs/optics.en.md](docs/optics.en.md) (English) and [docs/optics.zh.md](docs/optics.zh.md) (Chinese) — those are written for *humans*; this file is for you.

## Project in one line

Any application — egui, games, editors, overlays — can give any region an Apple Liquid-Glass-grade glass material: `sdRoundedBox` SDF → bevel normals → `refract()` screen-space displacement → per-channel dispersion → Schlick–Fresnel edge glow. IOR is a real material constant (default 1.52, crown glass). **Optics are shared cross-platform; identity (corner radius, tint, control shapes) is per-platform.**

## Layout

```
vitreo/            # core crate: pure wgpu, zero UI deps
  src/glass.wgsl   #   the composite shader (single source of GPU truth)
  src/sdf2d.rs     #   CPU oracle: SDF + height + normals + jelly_* deformation (mirrors WGSL)
  src/optics.rs    #   CPU oracle: refract / dispersion / Fresnel (mirrors WGSL)
  src/panel.rs     #   GlassPanel (+ velocity/press motion inputs) + PanelUniform (96-byte layout, must match WGSL)
  src/style.rs     #   GlassStyle / ShadowStyle (the public material API)
  src/backdrop.rs  #   backdrop textures: static from_rgba / from_view + LiveBackdrop (offscreen, GPU mips)
  src/compositor.rs#   multi-panel compositor (max 8 panels, Stack/Merge strategies)
vitreo-egui/       # egui binding crate (P3): pure egui/winit glue, zero wgpu-surface opinions
  src/spring.rs    #   spring integrator (smooth/bouncy presets) — the animation oracle
  src/animated.rs  #   AnimatedPanel: springs over center/size/radius/press; velocity feeds GlassPanel
  src/layer.rs     #   GlassLayer: compositor + panels + drag state machine + LiveBackdrop + DPI
  src/frame.rs     #   EguiFrame: egui-wgpu/winit per-frame wiring (incl. textures_delta fix)
examples/minimal   # gradient/image backdrop + draggable spring panel (egui params)
examples/live-backdrop  # glass refracting the app's own offscreen scene; M toggles Merge
docs/optics.*.md   # physics report (EN primary, ZH translation)
docs/figures/      # bilingual figure pipeline, see below
```

## The parity invariant (most important rule)

The same math exists in **four** places that must never drift:

1. `vitreo/src/sdf2d.rs` + `vitreo/src/optics.rs` (CPU, tested),
2. `vitreo/src/glass.wgsl` (GPU),
3. `docs/figures/generate.py` (NumPy, figures),
4. `vitreo/src/panel.rs` (96-byte uniform layout ↔ WGSL `PanelData`).

If you change any formula, update **all** of them in the same commit, run the tests, and regenerate the figures. The CPU tests are the oracle; a WGSL-only "fix" that skips them is a bug.

## Build, test, verify

```sh
cargo build --workspace   # incremental is usually fast
cargo test  --workspace   # 49 vitreo tests (optics/sdf/layout/strategy/jelly) + 18 vitreo-egui tests + doc tests
cargo clippy --workspace  # keep it clean
```

- **Never commit unverified code.** Build + test before every commit; state the result in the commit body when it matters.
- Commit messages in English, imperative mood; commit often, one logical change per commit.
- On optics changes: `.venv/bin/python docs/figures/generate.py` (creates `.venv` via `python3 -m venv .venv && .venv/bin/pip install matplotlib numpy` if missing) and commit regenerated `docs/figures/*` together with the math change.

## Docs policy

- User-facing documents are **English primary with a full Chinese translation** (`*.en.md` / `*.zh.md`), paper-style: derive from the literature, explain every physical term, cite sources.
- Figures are bilingual (EN + ZH labels) and always generated by `docs/figures/generate.py` — never hand-drawn placeholders. The script re-derives the actual formulas, so it doubles as a parity check.
- Figure gotcha: strings mixing CJK with `$...$` go through matplotlib mathtext, which has no per-glyph CJK fallback. Keep them in separate runs or use Unicode subscripts; fonts are pinned to Arial Unicode MS in `setup_fonts()`.

## License & attribution (non-negotiable)

- Vitreo is **MIT** (`LICENSE`).
- Ported code (currently m2-md/liquid-glass-refraction-shader, jeantimex/glass-effect-webgpu, both MIT) must keep its credit in the module header, in `docs/optics.*.md` §9, and in the README. New sources get credited in all three places.
- **Never** copy code from a project whose license is incompatible with MIT or unknown. If you cannot verify the license, do not paste; reimplement from the physics and cite the *idea*.

## Philosophy

- Focus on the product. No anti-piracy, no DRM, no phone-home, no telemetry.
- Code is a tool to change the world, not a private profit artifact. Prefer clarity over cleverness; prefer honest physics over cheap tricks (e.g. fake refraction via blur).
- When you genuinely don't know — ask the maintainer, and stop; don't guess silently.

## Runtime caveats (slow machine)

- The maintainer's machine is slow. Toolchain/build steps that take minutes are normal; be patient with long-running commands.
- GUI examples (`examples/minimal` etc.) open a window and block the shell until closed. **Announce before launching one**, expect "unresponsive" pauses while it runs, and never kill it just because it looks stuck.
